# Publishing packages

Validate without publishing:

```sh
workspace-publish css-expand-collapse --dry-run
```

A dry run performs the publish checks without registry mutation. It checks registry state, verifies the matching Git release tag by default, and validates versions that would need publishing. A missing or mismatched release tag is reported as a warning instead of failing the preview. The JSON result includes `dryRun: true`, `verifyGitTag`, `gitTags`, `canPublish`, registry states, and the reason when publishing is blocked.

To preview every publishable workspace package:

```sh
workspace-publish --dry-run
workspace-publish --dry-run --json
```

Automation may wrap these commands, but the CLI remains the source of truth for publish validation.

Publish to GitHub Packages:

```sh
workspace-publish css-expand-collapse --registry=github
```

Stage a release for npm:

```sh
workspace-publish css-expand-collapse --registry=npm
```

Before a real publish, Git tag verification is enabled by default. The matching `<package-directory>@<package.json.version>` tag must exist and point to `HEAD`. A missing tag or a tag on another commit fails the publish before package validation or registry mutation.

To intentionally bypass this condition:

```sh
workspace-publish css-expand-collapse --no-verify-git-tag
```

If the matching tag is valid but the package version already exists in the selected registry, that destination is skipped with reason `already-published`.

Use `--registry=both` for both destinations. `--tag=<tag>` controls the npm distribution tag and `--access=public|restricted` controls access.

Before publishing a missing registry version, the tool runs each package's `typecheck`, `test`, and `build` scripts when present, followed by `npm pack --dry-run`.



## Publishing workspace-tools itself

This repository publishes `@moyarich/workspace-tools` to GitHub Packages.

The repository-local release workflow performs:

```text
typecheck
→ tests
→ build
→ npm pack --dry-run
→ create v<version> Git tag
→ publish package to GitHub Packages
→ publish matching GitHub Release
```

The repository's release process is fully self-contained and does not depend on any other `moyarich/*` repository or package.
